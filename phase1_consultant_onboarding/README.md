## Behavioral Research Framework

### What We Observe (The Signals)

#### Language Patterns
- Which explanations get rephrased in client conversations?
- What words still cause over-interpretation?
- How do consultants naturally frame the value proposition?

#### Process Friction
- Where do consultants hesitate or backtrack?
- Which steps get skipped or rushed?
- What workarounds emerge under time pressure?

#### Client Expectations
- What level of automation do clients expect?
- Which artifacts are actually requested by banks?
- How well do clients understand draft-only posture?

#### Professional Boundaries
- When do scope discussions occur?
- How well are legal service boundaries maintained?
- What reinforces vs. dilutes the positioning?

### What We Don't Ask (The Research Method)

This is **behavioral observation**, not surveying. We watch what people *do*, not what they *say* they would do.

- Don't ask "What did you think?" - watch hesitation patterns
- Don't ask "Was this confusing?" - observe backtracking
- Don't ask "What would you change?" - note workarounds used

## Data Analysis Approach

### Immediate Insights (Session-Level)
- Hesitation points (>3 seconds)
- Rephrased explanations
- Skipped elements
- Question patterns

### Pattern Recognition (Cross-Session)
- Common friction points
- Language that consistently fails
- Expectations that differ from design
- Boundary challenges

### Refinement Prioritization (Phase 2 Input)
- Language hardening (highest impact, lowest effort)
- UX friction fixes (≤5 items)
- Documentation improvements
- Training enhancements

---

## Risk Management

### Session Safety Protocols
- **Stop rule**: If consultant expresses significant confusion, pause and clarify
- **Boundary rule**: If scope creep occurs, reinforce draft-only posture immediately
- **Escalation rule**: If client misunderstanding creates liability risk, involve compliance

### Data Quality Controls
- **Observation consistency**: Same observer protocol across sessions
- **Pattern validation**: Cross-reference insights across consultants
- **Bias checking**: Compare observed behavior vs. self-reported preferences

### Exit Criteria
- **Success threshold**: Clear refinement opportunities identified without critical safety issues
- **Failure threshold**: Behavioral workarounds that compromise draft-only posture
- **Extension rule**: If patterns unclear, add 1-2 more sessions before deciding

## Phase 1 Exit Decision Framework

### Proceed to Phase 2 If:
- ✅ **Behavioral validation complete**: Real usage patterns documented
- ✅ **Safety maintained**: No compromises to draft-only posture
- ✅ **Refinement path clear**: ≤5 concrete improvements identified
- ✅ **Consultant readiness**: Can handle real client conversations
- ✅ **Platform stability**: No critical UX breakdowns observed

### Extend Phase 1 If:
- ❓ **Patterns unclear**: Need more sessions for reliable insights
- ❓ **Critical issues emerge**: Require deeper investigation
- ❓ **Consultant pool limited**: Need different consultant profiles

### Pause/Review If:
- ❌ **Safety compromise**: Behavioral workarounds undermine positioning
- ❌ **Major misunderstanding**: Consultants or clients fundamentally misinterpret scope
- ❌ **Platform issues**: Critical UX problems prevent completion

## Contingency Plans

### If Sessions Reveal Critical Issues
1. **Immediate**: Pause all consultant access
2. **Assessment**: Evaluate if issues are platform or positioning
3. **Remediation**: Address critical issues before resuming
4. **Documentation**: Update compliance pack with findings

### If Consultant Availability Limited
1. **Extension**: Add time for additional consultant recruitment
2. **Virtual option**: Consider remote observation sessions
3. **Modified scope**: Focus on highest-value consultants only

### If Platform Instability Emerges
1. **Investigation**: Determine if issues are environmental or systemic
2. **Hotfix**: Address critical stability issues immediately
3. **Rollback option**: Prepare contingency if fixes insufficient
