# Mobile saved worlds update

Start Your Journey now offers Open 3D World and Edit & Save My World for each saved world. The existing 3D view opens on troothhurtz.app and may need a separate website sign-in with the same credentials. The mobile editor is an explicit numeric placement editor, not an embedded 3D canvas: members can add already-owned assets, change position/rotation/scale, remove placements, save their private draft, reload, choose visitor access, publish the saved version, and copy the stable world address.

The new same-origin /api/mobile/worlds/[worldId] handlers reuse mobile session validation and active/approved member checks, enforce terms gating, reject administrators as member identities, and derive ownership from the session. Writes require the exact Origin and JSON, limit streamed input, validate finite transforms and unique placement IDs, check asset ownership and world-scoped licenses, and use a dedicated connection/transaction plus a world row lock. Snapshot hashes reject stale sessions with 409 rather than overwriting another edit. Failed writes roll back. Publishing copies the saved draft without altering visitor visibility. Responses are private/no-store. Private world data is cleared when the page is hidden; unsaved world changes are not stored offline.

World addresses retain the existing unique world ID and canonical /worlds/{id} route. Saving or renaming never creates another address. The mobile domain is a separate deployment; website/member database parity and visibility of a mobile-published snapshot on the website require an authenticated live acceptance check. The existing website draft endpoint must receive PR37 before it participates in the new world-row transaction lock; legacy website writes are not claimed to be serialized by this mobile-only change.

No account credentials, profile photos, avatars, registry entries or existing assets are changed by deployment. No schema migration, repository merge, catalog publication, PayPal activation, wallet connection or TROO transaction is included. Members can explicitly publish their own saved world with the new control. Real paid checkout remains disabled/unintegrated in mobile pending server-side receipt verification.

Validation: focused route/helper and jsdom tests exercise save/reload, rollback, stale revisions, owner access, ownership, input validation, publication/visibility, distinct addresses, numeric mobile editing and clearing private rendered state. CI also runs existing standalone tests and an optimized Next build/type check. Physical-phone and authenticated real-member round trips are separate acceptance items; do not infer them from mocked tests or a public login screen.
